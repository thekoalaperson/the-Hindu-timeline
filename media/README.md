# media/ — the film studio

Turns any story in this repo's corpus into a narrated, animated film: hand-authored
vector art and procedural animation, drawn live by one shared engine, driven almost
entirely by data (JSON + small per-story scripts) rather than bespoke code per film.
No AI-generated imagery or voices anywhere in the pipeline — see
[`engine/CONTRACTS.md`](engine/CONTRACTS.md) rule 4.

## Layout

| Path | What |
|---|---|
| [`engine/CONTRACTS.md`](engine/CONTRACTS.md) | **Read first.** The binding spec: hard rules (determinism, no deps, visual verification), the style bible, and the Person/Sets/Acting/Storyboard/Music APIs. |
| `engine/src/` | The engine itself, concatenated into every story page in `story.json`'s `engineFiles` order: `core.js` (math/easing/deterministic noise), `paint.js` (canvas drawing primitives), the character rig (`person.js`/`archetypes.js`, building on the original `people.js`), `acting.js` (pose presets), `wardrobe.js` (clothing/ornament rendering), `props.js` (static props + fauna rigs), `sets.js` (parallax environments), `stage.js` (the storyboard interpreter — `buildFilmFromStory()`), `player.template.html` (the player shell). |
| `engine/build/` | Node CLI tools, one job each: `lib.mjs` (shared helpers — story resolution, paths, the headless-Chromium path), `scaffold.mjs` (new story packages), `narrate.mjs` (TTS → timeline), `music.mjs` (procedural score), `mix.sh` (narration+music → master mix), `build-player.mjs` (assembles `dev.html`/`dist/index.html`/`dist/artifact.html`), `render.mjs` (headless frame render → MP4), `shots.mjs` (still-frame QA — the tool you use constantly), `validate.mjs` (storyboard sanity check, once landed). |
| `engine/test/` | Standalone dev pages (`lineup.html`, `zoom.html`) for eyeballing the rig itself — heads, figures, wardrobe — independent of any one story. |
| [`characters/registry.json`](characters/registry.json) | The reusable cast: character name → `{archetype, ...palette overrides, grounding, notes}`. Injected as the global `CHARACTERS` on every page by `build-player.mjs`, so `Person.of('krishna')` works in any story without redefining him. Covers the shipped Draupadī cast plus ~17 forward-looking characters (Rāma, Sītā, Hanumān, Rāvaṇa, Durgā, …), each grounded with a repo-path citation. |
| `stories/<slug>/` | One story package: `story.json` (manifest — files to load, narration/music/video config), `script.json` (narration text + pacing + mood, hand-written), `cast.js` (this story's character styles), `timeline.json`/`timeline.js` (**generated by `narrate.mjs` — never hand-edit**), `film.js` (scene authoring — storyboard JSON and/or JS scene functions), `audio/`, `dist/index.html` + `dist/<slug>.mp4` (committed outputs), `dist/artifact.html` + `dev.html` (regenerated on demand, gitignored). |

`stories/winning-of-draupadi/` is the shipped reference implementation — when in
doubt about shape or register, look at what it actually does.

## The make-film flow, in 5 lines

1. **Ground** the story in the corpus (`04-deep-dives/`, `timeline/`,
   `90-literature-corpus/`) — extract beats, names, epithets, cited variants.
2. **Scaffold + script**: `node engine/build/scaffold.mjs --slug <slug> --title
   "..."`, then write `script.json` (6-9 scenes, display + phonetic `tts`, mood).
3. **Cast**: reuse [`characters/registry.json`](characters/registry.json) via
   `Person.of(name)`, or define new characters by archetype + palette in `cast.js`.
4. **Audio, timeline, scenes**: `narrate.mjs` → `music.mjs` → `mix.sh`; author
   `film.js` as storyboard JSON where possible; **QA-loop the stills with
   `shots.mjs` and actually look at them** before rendering.
5. **Render + deliver**: `render.mjs` → MP4; `build-player.mjs` → interactive
   player; publish `dist/artifact.html` as an Artifact, deliver the MP4, cross-link
   the corpus source doc, commit.

The full, precise, step-numbered procedure — including prerequisites, exact
commands, the QA bar, and troubleshooting — lives in
[`.claude/skills/make-film/SKILL.md`](../.claude/skills/make-film/SKILL.md). That
skill is what makes "make a film of `<story>`" a one-prompt operation; read it
before running any of this by hand.

## Swapping the narration provider

Set `narration.provider` in a story's `story.json` (`engine/build/narrate.mjs` reads it):

| Provider | What it is |
|---|---|
| `pico` (default) | SVOX Pico (`pico2wave`) — classic rule-based diphone TTS, offline, no neural voices. |
| `espeak` | `espeak-ng` formant synthesis — also offline; a lighter-weight fallback if `pico2wave` is unavailable. |
| `dir` | Your own recordings: drop WAV takes at `stories/<slug>/voice/<sceneId>.wav`; narration timing adapts to their actual length automatically. Use this for a real narrator's voice. |
| `elevenlabs` | Stub in `narrate.mjs` — wire an `ELEVENLABS_API_KEY` + fetch call there when/if you want neural TTS. Deliberately not implemented by default, so "no AI voices unless you explicitly opt in" stays true out of the box. |

Pitch/tempo shaping (the "storyteller register" EQ) applies to every provider
except `dir`, which is kept close to the natural recording.
